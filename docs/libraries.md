# Libraries & Technology Evaluation: MedTwin AI

## Comprehensive Technology Decision Matrix

| Library / Framework | Version | Purpose in MedTwin AI | Why Chosen | Pros | Cons & Limitations | Alternatives Evaluated |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **FastAPI** | `>=0.110.0` | Backend API Server & Swagger Documentation | Built on Starlette/Pydantic; native asynchronous execution; automatic OpenAPI 3.1 Swagger UI generation; clean dependency injection architecture. | - High performance ASGI execution<br>- Automatic interactive Swagger (`/docs`)<br>- Strong Pydantic typing and input validation | Requires ASGI runner (uvicorn); async context requires careful handling of blocking I/O | **Flask**: Simpler but lacks native async and built-in OpenAPI.<br>**Django REST**: Overly heavy for a focused RAG microservice. |
| **Streamlit** | `>=1.32.0` | Interactive Web User Interface | Allows pure Python UI development with reactive state re-rendering; native microphone recording widget (`st.audio_input`); rapid prototyping for evaluation. | - Zero JavaScript build pipeline<br>- Built-in state management (`st.session_state`)<br>- Native rich UI widgets (tabs, metrics, audio) | Whole script re-runs on user interaction unless fine-tuned with session state; limited custom DOM styling. | **Gradio**: Good for single model demos, but less flexible for multi-tab enterprise dashboards.<br>**React / Next.js**: Production standard, but requires Node.js, separate build step, and doubled development timeline for a 20-hr assignment. |
| **ChromaDB** | `>=0.4.24` | Vector Database (Persistent Vector Index) | Embedded, serverless vector store; native persistent on-disk storage (`./data/chromadb`); cosine similarity space; zero operational overhead. | - No separate daemon or Docker container required<br>- Persistent local storage<br>- Simple Python client API | In-memory indexing can face memory pressure beyond 1M+ vectors; single-node only. | **Pinecone / Weaviate**: Cloud-hosted, requires API keys and network latency.<br>**FAISS**: High performance but lacks metadata filtering and persistent collection management. |
| **Sentence-Transformers (`all-MiniLM-L6-v2`)** | `>=2.5.0` | Dense Semantic Embeddings | Produces 384-dimensional dense vectors tuned for semantic similarity; compact 80MB size; fast CPU inference (<15ms per chunk). | - Fast CPU latency without requiring CUDA<br>- High semantic clustering accuracy<br>- Fully local & offline execution | 512 token truncation window; not specifically fine-tuned on rare medical terminology. | **OpenAI text-embedding-3**: Requires cloud network calls and ongoing API fees.<br>**BioBERT / ClinicalBERT**: Higher medical accuracy but 5x larger and significantly slower on CPU. |
| **Ollama (`llama3.2` / `llama3`)** | Local CLI | Local LLM Inference Engine | Standardized open-source LLM runtime; provides HTTP REST endpoints (`/api/generate`); complete patient data privacy with zero external telemetry. | - True local edge privacy<br>- Supports open weights (Llama 3, Mistral, Gemma)<br>- Built-in model quantization | Requires local RAM/VRAM; latency varies based on host hardware. | **Hugging Face TGI / vLLM**: Excellent for server GPUs, but complex setup for local desktop evaluation.<br>**Llama.cpp**: Direct bindings, but harder to maintain cross-platform. |
| **OpenAI Whisper (`tiny`)** | `>=20231117` | Speech-to-Text (STT) Voice Input | Authoritative speech recognition model; tiny variant (39M parameters) runs on CPU in <1 second for typical symptom queries; high robustness to background noise. | - Robust multi-lingual STT<br>- Handles medical terminology well<br>- Runs directly on standard CPU | Occasional repetition hallucination on prolonged silent audio recordings. | **Vosk**: Lightweight but lower accuracy on medical and drug names.<br>**Google Cloud Speech**: Requires cloud billing and internet connection. |
| **SQLAlchemy + SQLite** | `>=2.0.28` | Relational Database & ORM | Embedded relational database with ACID compliance; zero configuration; robust schema migration and relationship management via SQLAlchemy 2.0. | - Single-file database (`medtwin.db`)<br>- Full SQL querying capability for analytics<br>- Zero external infrastructure required | SQLite write locks limit high concurrent write throughput (not a bottleneck for single-user/MVP). | **PostgreSQL**: Enterprise standard, but requires running external background service or Docker container.<br>**DuckDB**: Optimized for OLAP, but less mature ORM ecosystem for transactional user sessions. |
| **BeautifulSoup4 + Requests** | `>=4.12.0` | Clinical Data Ingestion Pipeline | Standard Python web scraping library; parses clean HTML structures and strips boilerplate navigation/scripts. | - Lightweight and reliable<br>- Easy DOM traversal and markdown conversion<br>- No browser binary required | Cannot execute dynamic JavaScript-rendered single-page applications. | **Scrapy**: Powerful but excessive overhead for 8 guideline articles.<br>**Playwright / Selenium**: Heavier headless browser footprint. |
| **Pytest + Pytest-Asyncio** | `>=8.0.0` | Automated Testing Suite | Industry standard Python testing framework with rich fixture ecosystem and async test support. | - Powerful parameterization and fixture injection<br>- Clear diffs on failure<br>- Native integration with coverage reporting | Requires pytest-asyncio plugin for async FastAPI endpoints. | **Unittest**: Built-in, but more verbose and lacks advanced fixture dependency chaining. |
